# v1.0.2 — In-App Update (APK khud download + install)

**Version:** 1.0.2+3 · **Build date:** 2026-11-20
**APK:** `apk/school-management-v1.0.2-universal.apk` (53 MB / 55,051,825 bytes)
**SHA-256:** `a5eb56398287efcd65f5d6532c5d947a4e8aa754f693747b609fc16dd230bc3f`

---

## Kya naya hai

v1.0.1 mein update check karne pe app sirf **browser khol** deti thi — user ko
khud APK download karke install karna parta tha. v1.0.2 mein poora kaam app ke
andar hota hai:

1. Settings → "Update Check" → app ko naya version milta hai.
2. **"Naya update hai, download karein?"** → tap karein.
3. APK **app ke andar download** hota hai (progress bar ke saath).
4. Download **sha256 se verify** hoti hai.
5. Android ka **installer screen khul jata** hai → sirf "Install" dabana hai.

Ek cheez Android ki majboori hai: **install ka final tap user ko khud karna
parta hai**. Koi app chupke se khud install nahi ho sakti (Android 8+ pe
`REQUEST_INSTALL_PACKAGES` permission chahiye hoti hai). App pehli baar us
permission ka screen kholti hai, phir installer.

### Badle hue files
- **`lib/services/update_service.dart`** — `downloadApk()` add hua: Dio se
  download, pehle `.part` file mein, phir sha256 verify, phir final naam pe
  rename. `verifySha256()` aur `sha256OfFile()` nikale gaye.
- **`lib/screens/settings_screen.dart`** — progress tile, unknown-sources
  permission dialog, "Browser mein" fallback.
- **`AndroidManifest.xml`** — `REQUEST_INSTALL_PACKAGES`, FileProvider
  `<provider>`, aur `<queries>` (Android 11+ package visibility ke liye).
- **`pubspec.yaml`** — `dio: ^5.11.1`, `crypto: ^3.0.8`, `version: 1.0.2+3`.
- **`version.json`** — naya `sha256` field + v1.0.2 ka `apkUrl`.

### Download pipeline ka flow
```
version.json  →  apkUrl + sha256
      ↓
Dio.download → <files>/apk/school-management-v1.0.2-universal.apk.part
      ↓  (sha256 verify — fail ho to file delete, error throw)
rename → <files>/apk/school-management-v1.0.2-universal.apk
      ↓
FileProvider content:// URI → ACTION_VIEW (application/vnd.android.package-archive)
      ↓
Android installer → user "Install" dabata hai
```

### Ek bug jo test ne pakda
Test likhte waqt pata chala ke **progress callback kabhi fire nahi ho raha tha**
jab server `Content-Length` header na bheje (dio tab `total = -1` deta hai).
Us surat mein UI ka progress bar **0% pe atka rehta** — jo user ko broken
lagta. Fix: `_progress` ab nullable hai; size maloom na ho to bar
**indeterminate (animated)** dikhta hai aur "Download ho raha hai..." likha
aata hai, jhootha percentage nahi.

## Naya release kaise karein (checklist)

1. `pubspec.yaml` mein `version:` barhayein (e.g. `1.0.3+4`).
2. `flutter build apk --release`
3. APK ko `apk/school-management-v1.0.3-universal.apk` naam dein.
4. `sha256sum` lein.
5. `version.json` update karein — **charo** fields:
   `version`, `apkUrl`, `sha256`, `releaseNotes`.
   > ⚠️ `sha256` bhool gaye to verification chup-chaap skip ho jayegi
   > (crash nahi karega, bas check nahi hoga).
   > ⚠️ `apkUrl` ka file naam APK ke naam se **exactly** milna chahiye.
6. `.gitignore` ki whitelist line nayi file ke naam pe update karein —
   warna nayi APK silently ignore ho jayegi.
7. Commit + push.
8. Confirm: `version.json` ka `apkUrl` browser mein khule aur **200** de.

## Yaad rakhne wali baatein

- APK **debug key se signed** hai → sideload ke liye theek hai, **Play Store
  pe upload nahi ho sakta**.
- Sha256 sirf **corruption/tampering** detect karta hai; HTTPS + GitHub ka
  trust model already hai. Signing key badalni ho to purani installs pe
  update install nahi hoga (signature mismatch).
- Shorebird abhi configure nahi hai — update hamesha **poora APK** hota hai.
